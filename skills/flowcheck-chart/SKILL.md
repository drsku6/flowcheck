# Flowcheck Chart

Build a verified Mermaid flowchart from a Wikipedia link, pasted text, or a file, using this repo's cards and tools. If asked to check an existing chart instead, use flowcheck-verify.

Run everything from the repo root.

## Workflow

1. Get the source text and pick sid (lowercase stem, a-z0-9-).
   - URL or file: `python ingest.py <file_or_url> --id <sid>` writes `workspace/<sid>_source.md`.
   - Pasted text: save it to `workspace/<sid>_source.md` yourself, and write the matching `workspace/<sid>_source.json` with keys source, url_or_null, title, fetched_at, chars, pages.
   - Up to 50000 chars is one chart. Longer sources are refused: shorten the text below 50000 chars first.
2. Draft each chart yourself from `cards/WRITER_CARD.md` plus the matching `cards/profiles/<type>.md` and `cards/STYLE_TARGET.mmd`. Classify short sources yourself (procedure, mechanism, classification, evidence, rules, general). Every bullet and labeled edge gets a `%% CLAIM` line with one complete verbatim source sentence.
3. Save the draft to `workspace/<sid>.mmd`. Run `python tools/inject_refs.py <chart> --id <sid>`, then `python tools/validate_mmd.py <chart> workspace/<sid>_source.md`.
4. On FAIL, fix only what the validator names (near-verbatim quotes first, replaced with the exact source sentence), re-run inject plus validate. One repair round only; remaining failures stay red (safetyNode class, red linkStyle, ⚠ bullet prefix).
5. Publish atomically: write to a temp file in `output/`, then `os.replace` to `output/<stem>.mmd`, prepended with `%% generated by muse-spark-1.2 via api.meta.ai | source: <source> | <date>`. Copy the report to `output/<stem>_report.md`. Names with existing output are skipped (headless reruns need `--force`); never touch other ids' files.

(Headless equivalent of steps 1–5: `python orchestrator.py input/<file>`, `--text "..." --id <name>`, or `--url <link> --id <name>`.)

6. Revise when the user asks to include or exclude something. Exclusions are
mechanical: delete the node, its CLAIM lines, and its edges. Inclusions must
come from the source: each added bullet needs a verbatim source sentence and
its own `%% CLAIM` line — anything not stated in the source is refused with
the reason, never invented. After any revision, re-run inject plus validate;
a dropped node that breaks reachability and any unsupported addition both
FAIL, so fix or refuse accordingly. Republish atomically and report what
changed plus what was refused and why.

## Rules

- Only facts stated in the source. Keep hedges and numbers exactly as written.
- Omit what is uncertain and list it as LOW-CONFIDENCE with why.
- Never edit the source, the cards, or another id's outputs.
